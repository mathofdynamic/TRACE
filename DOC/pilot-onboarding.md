# Controlled Pilot Onboarding

1. Confirm the team, repository, use case, execution mode, data policy, and support owner.
2. Use a dedicated staging/internal GitHub App before production installation.
3. Select only the repository required for the pilot and verify requested read permissions.
4. Start with local deterministic analysis; enable semantic analysis only after the quality gate is reviewed.
5. Generate one PR brief and one daily report; inspect evidence and limitations with the design partner.
6. Record finding dispositions, conflict confirmations, report usefulness, and support issues at organization level.
7. Export `.trace` artifacts and disconnect the repository as the exit test.

Regulated use, certification claims, unsupported retention guarantees, and unsupported languages are outside the pilot scope.
